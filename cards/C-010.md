## Scope

Thay PostgreSQL managed (GCP Cloud SQL `contract-analysis-g145-vinuni:asia-southeast1:fairterms-db` + service `cloud-sql-proxy`) bằng **1 container Postgres self-host chạy cùng VM với app**, để đỡ tốn tài nguyên/chi phí. Áp dụng cho **cả 3 môi trường** (local, dev, main).

Kiến trúc chốt: **1 container Postgres duy nhất, 2 database** trên VM dùng chung cho dev + main:
- `fairterms_dev` cho stack dev
- `fairterms_main` cho stack main
- Local tự chạy 1 container riêng (máy dev), database `fairterms`.

Vì `docker-compose.dev.yml` và `docker-compose.main.yml` là 2 compose project tách biệt trên cùng VM, container Postgres dùng chung được tách ra **`docker-compose.db.yml`** riêng, expose qua **external Docker network** (`fairterms-db-net`) để cả 2 stack join vào và trỏ host `postgres:5432`.

Các thay đổi cụ thể:
1. Tạo `deploy/docker-compose.db.yml`: service `postgres:16-alpine`, volume `pgdata`, healthcheck `pg_isready`, network `fairterms-db-net`, **không** map port ra host (chỉ nội bộ Docker network). Init script tạo 2 DB `fairterms_dev` + `fairterms_main`.
2. `docker-compose.dev.yml` / `docker-compose.main.yml`: xoá service `cloud-sql-proxy`; join `fairterms-db-net` (external); đổi `depends_on` sang chờ Postgres healthy (qua healthcheck app-side hoặc dựa vào entrypoint retry).
3. `docker-compose.local.yml`: thay `cloud-sql-proxy` bằng service `postgres` cục bộ (database `fairterms`); sửa/bỏ đoạn `sed` rewrite host ở command (dòng ~160) từ `cloud-sql-proxy:5432` → `postgres:5432`.
4. `src/frontend/docker-entrypoint.prod.sh` (dòng 6-7): rewrite host hard-code `cloud-sql-proxy:5432` → `postgres:5432`. **Bắt buộc rebuild + push lại image frontend** (dev + main) vì đoạn này baked trong image.
5. Env: thêm `POSTGRES_USER` / `POSTGRES_PASSWORD`; đổi `DATABASE_URL` host `127.0.0.1:5432` → `postgres:5432` với đúng tên DB mỗi stack. Cập nhật `.env.example`, `deploy/.env.dev.example`, `deploy/.env.main.example` (bỏ `CLOUD_SQL_INSTANCE`); cập nhật GitHub secrets `DEV_ENV_FILE` / `MAIN_ENV_FILE`.
6. Deploy: bỏ bước "start `cloud-sql-proxy` trước" trong `deploy/README.md` (Manual deploy + CI/CD note) và `deploy/setup-server.sh` nếu có; thêm `docker compose -f docker-compose.db.yml up -d` chạy trước 2 stack.
7. **Di chuyển dữ liệu**: `pg_dump` từ Cloud SQL → `pg_restore`/`psql` vào container mới cho từng DB, trước khi cắt hẳn. Script đặt ở `deploy/migrate-cloudsql-to-local.sh`.
8. **Backup**: thêm `deploy/backup-postgres.sh` + hướng dẫn cron `pg_dump` định kỳ (thay cho backup tự động của Cloud SQL).
9. `deploy/README.md`: viết lại mục "PostgreSQL (Cloud SQL)" thành self-host; ghi chú có thể gỡ IAM `roles/cloudsql.client`.

## Implementation notes (discovered during build)

- **CI workflows had to change** — both `deploy-*.yml` started `cloud-sql-proxy`; now
  they `docker compose -f docker-compose.db.yml up -d` and write `.env.db` from a new
  `DB_ENV_FILE` GitHub secret. Deploy would break without this.
- **New GitHub secret required: `DB_ENV_FILE`** = contents of `deploy/.env.db`.
- **Compose gotcha handled**: `env_file` values are NOT available for `${...}`
  interpolation, so `db.yml` reads `POSTGRES_USER`/`PASSWORD` from `.env.db` at
  container runtime; the healthcheck uses `$$POSTGRES_USER`.
- **Frontend entrypoint change is baked into the image** → dev+main frontend images
  MUST be rebuilt/pushed (CI does this automatically on next push).
